# API and client notes (verified 2026-11-04)

Facts below were checked against live sources on the date above. Where something could not be confirmed it says so. Re-verify anything marked "unconfirmed" before relying on it.

## WoW Forever client

- Launches 2026-11-04 23:00 UTC. Separate ruleset from Classic Era; characters do not transfer.
- Install folder: `_forever_` (WowUp 2.24 and the CurseForge app both key off this; beta used `_classic_beta_`). **Unconfirmed on a retail install until launch night.** Detect by folder name, prefer `.flavor.info` when present.
- TOC: `## Interface: 16001` (game version 1.60.1). Flavour-specific TOC suffixes: `_Forever.toc` and `_Camelot.toc` ("Camelot" is the internal codename; `_Forever` was added as an alias on 2026-10-08). `[AllowLoadGameType camelot]` conditionally loads a file on Forever only. `_Classic.toc` does **not** apply to Forever.
- Sources: forevermeta.me addon guide; forevermastery.com compatibility page; WowUp source (`WOW_FOREVER_FOLDER = "_forever_"`).

### Observed on the author's install (2026-11-04, pre-launch)

- `_forever_` exists; `.flavor.info` is `Product Flavor!STRING:0` then `wowf`. Others: `_classic_era_` → `wow_classic_era`, `_anniversary_` → `wow_anniversary`, `_classic_` → `wow_classic` (progression client, not a v1 flavour), `_retail_` → `wow`.
- Client executable: `Wow.exe` in `_forever_` and `_retail_`, `WowClassic.exe` in the Classic folders. Detection accepts either, or `.flavor.info`.
- Flavour TOC suffixes use `_` or `-` (`Questie-Classic.toc`, `Details_TinyThreat-Classic.toc`). Some addons ship no plain `.toc` at all (ElvUI, WeakAuras).
- Multi-folder addons do not always use a separator (`WeakAurasOptions`), and module folders often carry no IDs (`LittleWigs_*` depend only on `BigWigs`).
- GitHub release asset downloads now redirect `github.com` → `release-assets.githubusercontent.com` (not `objects.githubusercontent.com`). Assets carry `digest: "sha256:…"`.
- WoWInterface `filedetails` has `UIMD5` but no `UICompatibility`; flavours come from `filelist.json`. No entry lists `1.60` yet.
- Image hosts: WoWInterface `UIIMG_Thumbs` / `UIIMGs` → `cdn-wow.mmoui.com`; GitHub `owner.avatar_url` → `avatars.githubusercontent.com`; Wago thumbnails → `cdn.wago.io` (seen on addons.wago.io). CurseForge logos/screenshots are expected on `media.forgecdn.net` but **unconfirmed** (the site returns 403 to scripts and the docs show placeholders); confirm from the first recorded CurseForge response.

## GitHub Releases (no key)

- `GET https://api.github.com/repos/{owner}/{repo}/releases?per_page=10` — unauthenticated limit 60 requests/hour per IP; honour `X-RateLimit-Remaining` / `X-RateLimit-Reset`. Optional PAT via `Authorization: Bearer` raises this to 5000/hour.
- Prefer releases that carry a `release.json` asset (generated by BigWigsMods/packager). Its shape:
  ```json
  { "releases": [ { "filename": "Addon-1.2.3.zip", "nolib": false,
      "metadata": [ { "flavor": "forever", "interface": 16001 }, { "flavor": "classic", "interface": 11509 } ] } ] }
  ```
  Pick the entry whose `metadata[].flavor` matches and `nolib == false`.
- Without `release.json`, pick by asset name suffix (table above); an asset with no flavour suffix is treated as "all flavours" only if the repo's TOC files say so (fetch `{raw}/{Addon}.toc` is **not** worth it; just mark the release as flavour-unknown and let the user confirm).
- Download the asset's `browser_download_url` (hosts: `github.com` → redirects to `objects.githubusercontent.com`).
- Identify a repo from a TOC: `## X-Website: https://github.com/owner/repo` or `## X-GitHub`.
- Seed catalogue: there is no GitHub-wide index, so Nexforge bundles one: `crates/nexforge-core/data/github-index.toml` (30 addons). It maps the CurseForge / Wago / WoWInterface IDs in an addon's TOC to the GitHub repo that publishes its releases, so reconcile, search and `install <name>` use GitHub for addons whose TOCs only name CurseForge or Wago (Questie, Plater, RXP, WeakAuras …).
  - Verification rule (2026-11-04): the repo's own TOC carries the same IDs as the installed addon, **and** the repo publishes zip releases. A name match alone is not enough.
  - Left out after checking: Details (`Tercioo/Details-Damage-Meter` has had no zip releases since 2021), ElvUI_ToxiUI and ReforgedArmory (no releases), LFGBulletinBoard (the matching repo has no releases; likely a copy). Not on GitHub with matching IDs: Leatrix Plus, Engraver, Pawn, TradeSkillMaster, Zygor.
  - Repos whose newest `release.json` already lists `forever` (2026-11-04): BetterBlizzFrames, BetterVendorPrice, BigWigs, DBM, ElvUI_WindTools, HandyNotes, LiteMount, PallyPower (beta), Plater, Questie, RXPGuides, RatingBuster, SilverDragon.
  - Shared repos: an entry may set `tag = "x"` to take only releases tagged `x/…`; its source id is `owner/repo#x`. Spoken (`rusty-key/spoken-wow`) releases its desktop app (`manager/…`), the addon (`spoken/…`) and voice packs (`quests-audio/…`, `readables-audio/…`, `places-audio/…`, `bosses-audio/…`, plus other languages) from one repo, so each is its own entry. A bare repo URL maps to the repo's first entry, never the whole repo.
  - Voice packs declare `X-Part-Of: Spoken`, so reconcile never merges two folders the index knows as different addons, and an update only removes a dropped folder if a Nexforge-installed archive put it there (adopted folders stay and get their own entry).
  - Looked for and **not** indexed (2026-11-04): DialogueUI (only a third-party translation plugin on GitHub, nothing on WoWInterface); EnhanceQoL (WoWInterface 26888 lists Retail only; the GitHub copies have no releases); Chattynator (`plusmouse/Chattynator` does not exist; the only repo with releases is a re-upload by someone else); Forever++ (nothing found); DungeonJournal by ExehnTV (CurseForge project 1707971, game version 1.60.1, "All Rights Reserved", no source link; no GitHub repo or WoWInterface listing; `lokiy999/DungeonJournal` is an unrelated 1.12 addon).
- Confirmed on Questie `bundle/v12.5.1+v1.0.10` (2026-11-04): the Forever build ships `Questie_Forever.toc` with `## Interface: 16001`, and its release.json labels it `forever`.

## WoWInterface (no key)

- Base: `https://api.mmoui.com/v3/game/WOW/`
- `filelist.json` — every addon: `UID`, `UIName`, `UICATID`, `UIVersion`, `UIDate` (ms epoch), `UIAuthorName`, `UIDownloadTotal`, `UIDir` (folder names), `UICompatibility[]` (`{version, name}`). ~2 MB; cache 24 h; this seeds the catalogue.
- `filedetails/{id}.json` — adds `UIDownload` (the zip URL), `UIHitCount`, `UIDescription`, `UIChangeLog`, `UIImageSmall`/`UIImageThumbs` (icons).
- Identify from TOC: `## X-WoWI-ID: 12345`.
- No flavour field beyond `UICompatibility`; map `version` prefixes per the table. Treat missing compatibility as flavour-unknown.
- Download host: `cdn.wowinterface.com` (follow redirects from `www.wowinterface.com`).
- Source: wowa package `mmoui.js`; Minion and instawow use the same endpoints.

## Wago.io Addons (key required, paid)

- **Correction 2026-11-04:** an API key is not free. Wago asks for a Patreon subscription before it issues one (reported by the author while signing up). Treat Wago as an opt-in source for subscribers; nothing else may depend on it.

- Base: `https://addons.wago.io/api/external`
- Auth: `Authorization: Bearer <key>` on every call. Keys from the Wago developer portal; WowUp's own key is not ours — the user registers one.
- `GET /addons/_search?query=<q>&game_version=<gv>` → `{ data: [ { id, display_name, summary, thumbnail_image, authors[], download_count, website_url, releases: { stable?, beta?, alpha? : { label, download_link, created_at, logical_timestamp } } } ] }`
- `GET /addons/popular?game_version=<gv>` → same shape.
- `GET /addons/{id}` → `{ id, slug, display_name, summary, description, authors[], thumbnail_image, gallery[], website_url, download_count, recent_releases: { stable?, beta?, alpha?: { label, stability, download_link, created_at, changelog, supported_retail_patch, supported_classic_patch, supported_bc_patch } } }` (note: some responses say `recent_release`, singular — accept both).
- `POST /addons/_recents` body `{ game_version, addons: [id, …] }` → `{ addons: { [id]: { id, name, thumbnail, website_url, authors[], cf, wago, wowi, matched_release?, recent_releases: { stable?, beta?, alpha?: { id, created_at, label, patch, supported_patches[], link? } } } } }` — use for batch update checks.
- `POST /addons/_match` body `{ game_version, addons: [ { name: <folder>, hash: <folder fingerprint>, cf?, wowi?, wago? } ] }` → same per-addon shape plus `modules: { [folder]: { hash } }`. Use for reconcile: it matches by TOC IDs and by folder hash. Fingerprint = WowUp's folder hash (sha256 over sorted file paths + contents, excluding `.git`); if we don't replicate it exactly, matching still works on `cf`/`wowi`/`wago` IDs.
- `download_link` expires (`logical_timestamp`); fetch details right before downloading.
- `game_version` values: `retail | classic | bc | wotlk | cata | mop | forever`.
- Identify from TOC: `## X-Wago-ID: AbCdEf12`.
- Source: WowUp `wago-addon-provider.ts` (cloned 2026-11-04).

## CurseForge (key required; coverage partial)

- Base: `https://api.curseforge.com/v1` with header `x-api-key: <key>`. Keys from the CurseForge for Studios console; third-party apps may be refused or rate-limited, and **authors can opt out of third-party distribution**, in which case `files[].downloadUrl` is `null` and the addon must be shown as "unavailable from CurseForge".
- Game ID for WoW: `1`.
- `GET /mods/search?gameId=1&searchFilter=<q>&gameVersionTypeId=<id>&sortField=2&sortOrder=desc&pageSize=50`
- `GET /mods/{id}` and `POST /mods` body `{ modIds: [...] }` for batches; `GET /mods/{id}/files?gameVersionTypeId=<id>`.
- File flavour: `files[].sortableGameVersions[].gameVersionTypeId` must include the installation's type id (table above). `releaseType`: 1 release, 2 beta, 3 alpha.
- Identify from TOC: `## X-Curse-Project-ID: 123456`.
- Changelog: `GET /mods/{id}/files/{fileId}/changelog`.
- Shapes re-checked against docs.curseforge.com on 2026-11-04: `allowModDistribution`, `latestFiles`, `latestFilesIndexes[].gameVersionTypeId`, `files[].hashes[].algo` (1 = SHA-1, 2 = MD5), `releaseType` (1 release, 2 beta, 3 alpha), search params `slug` and `gameVersionTypeId`, `POST /mods` body `{ modIds, filterPcOnly }`.
- Implemented in `sources/curseforge.rs`. On only while a key is saved (`nexforge key set curseforge` turns it on, `key clear` off). Downloads are verified with the file's MD5. A null `downloadUrl` (author opted out) is never worked around: no URL is built from the file id; the player is told the author does not allow downloads outside the CurseForge app.
- **Tests use synthetic fixtures** (`tests/fixtures/curseforge/`, see its README); nothing could be recorded without a key. Record real responses as soon as one is available, and confirm the Forever `gameVersionTypeId` (88568) and the `media.forgecdn.net` image host from them.
- Source: WowUp `curse-addon-provider.ts` (`GAME_TYPE_LISTS`), CurseForge docs.

## Folder hygiene

- Ignore `AddOns/Blizzard_*`, any file at the top level, and folders without a `.toc`.
- Multi-folder addons are common (Questie: 4, DBM: 9). Group by shared `X-*-ID`, then by `## Dependencies`, then by a common prefix only as a last resort shown to the user.
- `-nolib` releases omit bundled libraries; never pick one unless the user asks.
